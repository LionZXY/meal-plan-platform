# Формат данных рациона

Всё меню и его ресурсы находятся в `content/`. Код интерфейса находится в `src/` и `public/`. Для замены всего рациона достаточно изменить JSON и изображения в `content/`: GitHub Actions проверит их и опубликует сайт.

## Каталог

`content/catalog.json`:

```json
{
  "schemaVersion": 1,
  "locale": "ru-RU",
  "timeZone": "Europe/London",
  "people": [{
    "id": "nikita",
    "name": "Никита",
    "plans": [{
      "id": "nikita-2026-10-10",
      "title": "Рацион на 10–16 октября",
      "startDate": "2026-10-10",
      "endDate": "2026-10-16",
      "file": "plans/nikita-2026-10-10/plan.json"
    }]
  }, {"id": "nastya", "name": "Настя", "plans": []}]
}
```

IDs: строчные латинские буквы, цифры и дефисы. Даты: существующие календарные даты `YYYY-MM-DD`. Имя можно изменить, сохранив ID: выбор в браузере привязан к ID. Пустой `plans` показывает состояние «рацион пока не добавлен». Для дополнительной недели добавьте новую запись в `plans`; селектор недель появится автоматически. Первая и последняя даты записи должны совпадать с датами файла рациона.

Периоды одного человека не должны пересекаться: на каждую дату должен однозначно выбираться один рацион. У разных людей могут быть одинаковые даты. В путях ресурсов не должно быть начальных или конечных пробелов.

## Файл рациона

Обязательные поля `plan.json`:

| Поле | Содержание |
|---|---|
| `schemaVersion` | `1` |
| `id`, `personId` | ID рациона из каталога и ID его владельца |
| `title` | Заголовок |
| `products` | Объект продуктов, ключ — ID продукта |
| `days` | Массив дней с уникальными датами |

Продукт содержит `name` (русское название с пояснением веса), `originalName` (исходное английское название), `unit` (`g` или `ml`) и `nutritionPer100` с числами `kcal`, `protein`, `fat`, `carbs`. Необязательные поля: `packageSize`, `url`. КБЖУ должны соответствовать выбранному продукту и состоянию, в котором указан его вес, на 100 г или 100 мл. Для значения «менее X» укажите используемое числовое допущение в `nutritionNote`.

Каждый день: `date` и `meals`. Каждое блюдо: уникальный в пределах дня `id`, `type`, `title`, `ingredients` и `instructions`. Ингредиент: `productId` и положительное число `amount`. Инструкция — обычный текст. Итоги блюд, дней и среднее вычисляются автоматически; отдельные итоговые числа в JSON не нужны.

Необязательное поле блюда `sharedPrepNote` содержит пометку о совместном приготовлении, например «Также готовим для Насти». Она видна под названием блюда. Добавляйте её только после сравнения даты, приёма пищи, блюда и состава в обоих рационах. Граммовки могут отличаться. Если меняете меню, обновите или удалите пометку в обоих рационах. Без этого поля карточка не показывает пометку.

Пример структуры блюда (числа ниже демонстрационные):

```json
{
  "date": "2026-10-17",
  "meals": [{
    "id": "lunch",
    "type": "Обед",
    "title": "Блюдо из примера",
    "ingredients": [{"productId": "example-product", "amount": 200}],
    "instructions": "Инструкция приготовления выбранного продукта.",
    "image": {"src": "images/lunch.jpg", "alt": "Описание подачи блюда"}
  }]
}
```

## Дополнительные разделы и изображения

Необязательные поля:

- `description`, `revision`, `portionNote`, `nutritionNote`, `sourceNote`: обычный текст.
- `hero`: `{ "src": "images/hero.jpg", "alt": "Описание" }`.
- `facts`: массив `{ "value": "3 часа", "label": "на заготовку" }`.
- `prep`: `duration`, `equipment`, необязательный `note` и `steps` — массив `{time, title, text}`.
- `storage`: `rules` — массив `{title, text}`, `rows` — массив `{product, when, note}`. Необязательны `note`, `url` и `details: {title, text, items: [{label, text}], footer}`.
- `shopping`: необязательный `note` и `groups` — массив `{name, items: [{productId, quantity}]}`. `quantity` — целое число упаковок от 1.

Пути картинок считаются относительно `plan.json`. Складывайте файлы в папку этого рациона, например `content/plans/nikita-2026-10-17/images/`. Можно использовать абсолютные HTTP(S) URL изображений. Локальные изображения проверяются на существование при сборке. Иконки оригинальных названий добавляются автоматически.

Не используйте пути от корня сайта `/images/...`, `..`, JS/HTML URL или HTML вместо текста. Это нарушает переносимость на GitHub Pages или отклоняется валидатором. Файлы с логинами, паролями, адресами доставки и сырыми ответами личного аккаунта не относятся к рациону.

## Проверка и публикация

```sh
npm ci
npm test
npm run validate
npm run build
npm run preview
```

Для проверки пути проекта: `npm run preview -- --base /meal-plan-platform/`.

После изменения только `content/` достаточно commit и push в `main`. Workflow `.github/workflows/pages.yml` проверяет данные и тесты перед публикацией. В `dist/` попадают только приложение и данные, без тестов и документации. Сборка использует версионированные пути, чтобы новые меню и изображения не зависели от старого кэша. Не редактируйте `dist/` вручную.
