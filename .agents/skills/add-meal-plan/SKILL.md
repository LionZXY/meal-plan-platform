# Добавление рациона

Работайте с репозиторием, у которого `package.json` содержит имя `meal-plan-platform`. Если текущая папка другая, используйте локальный файл `references/project-location.md`, когда он присутствует, или уточните расположение репозитория. Прочитайте `docs/content-format.md` в корне найденного проекта и актуальный `content/catalog.json`.

Меню и ресурсы находятся в `content/`, а приложение — в `src/` и `public/`. Для добавления рациона не меняйте приложение, тестовые фикстуры или `dist/`.

1. Найдите человека по стабильному `id`; не заменяйте его только ради изменения имени. Для нового человека добавьте запись каталога. Не заполняйте отсутствующий реальный рацион выдуманными данными: тестовые меню остаются в `tests/`.
2. Создайте папку `content/plans/<person-id>-<first-date>/` с `plan.json` и `images/`, либо измените существующий рацион, если именно это запросил пользователь. Перенесите все блюда, граммовки, инструкции, продукты и ограничения из согласованного рациона.
3. Укажите исходное английское название продукта, единицу `g`/`ml` и проверенные КБЖУ на 100 единиц. Различайте сырой, готовый и сухой вес, а также вес без жидкости. Итоги вычисляет приложение: не копируйте вручную итоговые КБЖУ. Не добавляйте компенсирующие продукты, если запрос — просто исключить ингредиент.
4. Положите изображения в папку рациона и укажите относительные пути и `alt`. Добавьте приготовление, хранение и список упаковок, если они есть в исходных данных. В данных для публичного сайта не нужны пароли, адреса доставки и сырые ответы личных аккаунтов.
5. Подключите `plan.json` к `people[].plans` в каталоге. `id` и `personId` должны совпадать; `startDate`/`endDate` равны первой/последней датам файла. Для новой недели сохраните ранее существовавшие недели, если их удаление не запрошено.
6. Выполните `npm test`, `npm run validate`, `npm run build`. Проверьте человека, даты, изображения, оригинальные названия и порции в локальном предпросмотре. Новые данные должны проходить существующие тесты; не ослабляйте проверки ради ошибочного меню.
7. Если публикация входит в запрос, сохраните изменения `content/` в Git и отправьте в `main` настроенного GitHub-репозитория. GitHub Actions публикует после успешных проверок. Подтвердите результат workflow и сообщите URL сайта. Если внешняя публикация недоступна, сохраните готовые данные и отдельно сообщите ограничение.

Для нового рациона с пищевыми целями или вопросами безопасности используйте актуальные исходные этикетки и профильные источники. Наличие этого скилла само по себе не разрешает менять корзину магазина или оформлять заказ.
